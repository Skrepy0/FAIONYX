## 2. 启动问题诊断与证据

### 结束游戏与启动状态竞争

发现两处独立原因：

1. 原主进程允许启动准备阶段的并发调用，`current` 会被后一个 Java 覆盖；任何旧进程的退出都能清空全局状态。现在使用会话 token，从准备到实际进程关闭持续锁定，旧事件不能清除新会话。所有入口仍调用现有启动服务。
2. 实际测试自动选中了 `C:\Program Files\Common Files\Oracle\Java\javapath\java.exe`。这个入口转发到真正的 JDK：测试观察到实际游戏 PID `87284`，父 PID `67440`。结束转发程序不能证明游戏已退出。

首次真实回归（修复 Java 转发前）失败在 `assert(!launch.isBusy())`，游戏进程仍存在。现改为读取 `java -XshowSettings:properties -version` 的 `java.home`，解析至 `C:\Program Files\Java\jdk-25.0.2\bin\java.exe` 后启动；停止操作等待进程 `close`，失败/超时不能宣告成功。未批量结束其他 Java，也未改动用户世界。

## 6. 桌面检查限制与剩余风险

- computer-use 技能用于真实窗口只读截图检查，并要求输入失败后重新绑定再试。点击操作连续返回 `foreground window did not report a process id`，重试仍失败，因此停止原生鼠标输入，没有伪造点击/拖动成功。
- 首页普通窗口成功显示实际 QA 离线账户和两个隔离实例；截图检查发现并修正了离线头像未裁头的问题。
- 高 DPI 检查日志：`width=960, height=620, dpr=1.5, overflow=false`；长名称区域宽144px、高32.5px，没有挤成逐字竖列。截图被另一个用户窗口部分遮挡，因此只把几何检测记为通过，不把完整视觉验收记为通过。
- 没有完成六主题逐个鼠标检查、连续拖动缩放、真实重命名拖选、原生多选框点击、所有开关点击和截图那台电脑的白屏复现。需要用户复核；两份可重跑验收脚本已提供。
- 游戏测试记录本机 Perflib 009 警告及离线账号访问 Realms/用户属性的认证错误；测试 JVM 仍持续运行20秒。这些日志不表示正版登录测试通过，也不应据此修改系统安全或注册表设置。
- 真实整合包并发验证出现一次 `MaxListenersExceededWarning`（11个 AbortSignal 监听器）；当前下载代码是既有实现，未证明泄漏，也未通过提高限制来掩盖。取消回滚成功，建议后续单独跟踪下载并发监听器生命周期。
- 皮肤缓存没有存放 access/refresh token；账号登录本身、网络请求失败情况下的实际皮肤刷新仍需要对应账号环境验收。
- 已关闭本次创建的 QA 启动器/Java 进程；未结束用户后来打开的其他启动器。临时 QA 文件保留供核对，未删除用户原有版本、存档、图片或旧发行 EXE。
