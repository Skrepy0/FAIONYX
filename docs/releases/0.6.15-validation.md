# FAIONYX 0.6.15 修复与验收

基线：opencode 的 0.6.14（64f0f98），保留全部既有功能。本次仅处理窗口材质、默认重点色、百科搜索词与便携启动路径。

## 成品

- `release/FAIONYX-0.6.15.exe`：85,177,366 字节。
- `release/FAIONYX-0.6.15-windows-x64.zip`：128,520,928 字节。必须完整解压到独立文件夹，再运行其中的 FAIONYX.exe；不能只拿出一个 EXE。
- SHA256 见同目录 `FAIONYX-0.6.15-SHA256.txt`。旧版本未删除或覆盖。

## 修复

1. Electron 33.4.11 的无边框窗口最大化会出现黑色 backdrop。单纯重新设置 Acrylic 在本机复测失败；完整修正包括清除 Chromium 设置的窗口裁剪 region、恢复 DWM 扩展客户区/材质/主题属性。保持原生 maximize/unmaximize 和窗口状态持久化，不使用截图背景或伪最大化。原生调用放在独立无窗口进程，只接受主进程拥有的 HWND；关闭后通过 stdin EOF 退出，错误不令主进程崩溃。
2. `THEME_PRESETS.transparent.colors.accent` 使用 `#81d8d0`。设置缩略图直接复用色板；不修改橙黑、粉黑等主题，也不强制切换用户当前主题。
3. 社区搜索结果保存 `originalTitle`。百科卡片和弹窗统一使用原始英文名，旧数据去掉追加的中文前缀；只有无可用英文原名时使用英文 slug。无英文名称/slug 时提示而不是提交中文查询。
4. 修正 electron-builder portable 模板中的未加引号 EXE 路径。beforePack hook 在内存中变换模板，不修改 node_modules；不认识的新模板会阻止构建，避免悄悄失效。使用每次启动独立解压目录，增加创建进程失败提示，并提供不经过 NSIS 自解压的 ZIP。

技术参考：[Electron 已报告的最大化材质问题](https://github.com/electron/electron/issues/46753)、[相关 Chromium 裁剪区域修正讨论](https://github.com/electron/electron/pull/46855)、[Microsoft DWM 客户区扩展 API](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmextendframeintoclientarea)。这些是定位依据，不代表本项目使用了已合并的新版 Electron 修复。

## 附件日志判断与边界

用户提供的 bug_log.zip 中 CSV 实际记录的是 **0.6.11**，不是 0.6.14。日志显示外层 32 位 portable stub 加载 NSIS 插件，最后退出码 1；未见内层 FAIONYX.exe 启动。用户附注表示完整解压后可正常运行。

本地依赖模板的 ExecWait 没有引用 `$INSTDIR\FAIONYX.exe`，而日志中用户目录包含空格。这是与证据吻合的明确启动缺陷，不应笼统归因为 Windows 11 版本过高、GPU 崩溃或 ASAR 损坏。日志也出现 RTSS hook，但不能仅凭加载记录断言其导致故障，因此未更改 RTSS、显卡、系统安全或透明效果设置。

**本机 Windows 10.0.26200 验证通过；未接入报告问题的 Insider 原机，不能宣称已覆盖所有 Insider build。** 若修正版 EXE 在原机仍失败，先使用 ZIP，并采集该次新日志进一步判断。
