## 3. P0 诊断状态：仍等待用户确认

本轮没有实现“启动后自动退出”或整合包崩溃修复，也不将原有诊断结果算作本版启动验收通过。

已有 [诊断报告](../diagnostics/launcher-auto-exit-and-modpack-crash.md) 区分了：

- 事实：spawn 后立即报告 running，自动退出固定 1500ms；此前纯净版自动退出开启时三次 Java 很快消失；代码中未找到自动退出直接调用 killGame 或递归杀进程树。
- 高可信推断：上层 Job/生命周期约束连带结束 Java；各自在 Job 中已观测，但同一个 kill-on-close Job 尚未完全证明。
- Forge 日志显示 Java 模块重复导出，推断是自定义实例 ID 与原版 client JAR 的 ignoreList/module path 冲突；Fabric 另有 ASM 9.10.1/9.6 重复类路径异常。
- 建议：确认后再实现可验证的独立进程与启动握手、修正对应参数/继承合并；不能用固定等待代替握手。
- 需要同一整合包和后续确认，才能完成原请求 2×2 多次启动最终矩阵。

好友房主的本机端口适配需保持 FAIONYX 运行；UI 和文档均告知不要自动退出。没有为了直连功能擅自改变游戏子进程退出策略。
