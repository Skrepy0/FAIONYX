## 3. 本轮四项完成情况与根因

### MOD 兼容识别：已实现并验证报告案例

代码证明的原问题有三个叠加因素：

1. 旧 `resolveBaseMcId` 对没有 inheritsFrom / _mcVersion 的扁平化版本使用 JSON id，导致 `26.2-NeoForge_26.2.0.66` 被当成 MC 版本；没有完整读取实际 Loader 版本。
2. 旧弹窗将区间中的逗号也拆成 OR，同时丢失左边界开闭含义；Fabric 的空格 AND 也按 OR 处理。
3. 旧候选只读当前目录的 `store.installed`，只用实例 id 标识，遗漏其他根目录并可能混淆同名实例。

新实现：

- 从实际启动 JSON、继承链、`clientVersion`、`--fml.mcVersion` / Loader 参数及 Maven 库坐标读取真实元数据，不解析显示名称/目录名称来匹配。
- 统一 Forge、NeoForge、Fabric、Quilt 的名称大小写、别名、Loader 版本前缀；支持四段以上数值版本、预发布后缀、精确版本、Maven 开闭/单边区间和区间并集、Fabric/Quilt 常用 AND/OR、通配符、caret、tilde。
- 扫描所有已注册根目录，规范化真实路径去重；候选用“目录 + id”定位。缺失元数据或扫描错误明确报告，不猜兼容、不假装已完整扫描。
- 安装时主进程重新校验兼容性并使用实例实际隔离 gameDirectory；同名 MOD 文件不静默覆盖。
- 有兼容实例时直接列出；确实无候选且扫描成功时才显示自动下载。自动下载也使用同一匹配器，不回退到已知不兼容版本。

真实只读证据：已注册目录中 `versions/26.2-NeoForge_26.2.0.66/26.2-NeoForge_26.2.0.66.json` 的实际参数解析得到：

```json
{"mcVersion":"26.2","loader":"neoforge","loaderVersion":"26.2.0.66","broken":false}
```

与 MC `[26.2]` / NeoForge `[26.2.0.57,26.3)` 匹配结果为 true。另读取真实 Fabric 扁平化 JSON，确认 `clientVersion: 26.2`、Loader `0.19.3`。UI 验收使用同约束的“仅元数据、不可用于游戏”测试 JAR，并实际列出上述真实 NeoForge 实例、所属目录、隔离状态；当前活动目录切换到 0 个版本的默认目录后，仍能找到另一目录中的该实例。

这证明版本识别及目标选择链路，并不等于本轮重新启动了原 MOD。用户截图对应的原 MOD JAR 本轮没有安装；未向真实游戏目录写入测试 JAR。

### 桌面像素启动过渡：已接入真实初始化

- 独立透明、无边框、鼠标穿透的桌面窗口，复用已有 `splash-face.png`，分解为 8×8 个独立像素块；散落、依次垂直升起、轻微摆动、等待、中心汇合。

- 主窗口隐藏加载，等待配置、账户、实例、首屏图片、Java、皮肤纹理、字体和首帧完成；初始化未结束时保持漂浮，不由固定秒数强行显示主界面。
- 主窗口显示门槛为 renderer 初始化完成 + compositor ready + 头像拼合完成。普通视觉运动采用 900ms 升起阶段和 620ms 汇合阶段，不是伪造初始化时长；汇合完成后再交给主界面，叠层淡出并销毁。

## 9. 仍存在的问题和验证边界

1. 已覆盖项目支持的 Forge / NeoForge / Fabric / Quilt 常用约束，不声称实际运行过所有历史 Minecraft 版本和所有 MOD。未知格式/不足的元数据采取不猜测兼容策略；复杂 Quilt 条件对象、任意历史快照的数值映射等不是本轮完整支持声明。
2. 元数据扫描及 JAR 解析仍复用原有主进程文件扫描机制；本机约 17 个版本响应很快，数千实例/慢磁盘未做性能压力测试。
3. 便携自解压、系统调度、GPU/DWM 合成、网络皮肤超时会影响冷启动总时长；动画不会伪造资源已加载。未量化 GPU 帧率和跨显示器动态 DPI。
4. 本轮只变导航，不重验真实公网 IPv6 / IPv4 / UPnP 双人游戏；原直连网络限制不变。
5. 全部六种主题配色未在本轮重新逐个验收；布局结构共用，透明主题在 100%/150%/200% 已检查，上一版本的六主题结果不能算本轮新测试。
6. 仍有基线 TypeScript 错误，原 P0 游戏自动退出问题尚未获准修复。没有用本轮 UI 测试代替游戏、账户和下载全矩阵。
